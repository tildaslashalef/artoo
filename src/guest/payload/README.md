# Guest baseline payload (`src/guest/payload/`)

Curated, shared configuration for every artoo guest (the guest user's
baseline fish/tmux/Vim environment), streamlined from the author's dotfiles. Embedded into the
artoo binary at comptime and rendered into the shared cloud-init
vendor-data snippet (`src/guest/vendor.zig`, SPEC §9.2); `artoo template
vendor` prints it. A new file here must also be listed in `vendor.zig`.

## Rules

- Shared baseline only. **Never** contains: secrets, SSH host keys, Tailscale
  state/auth keys, machine IDs, histories, universal variables, Mac paths,
  or per-guest identity. Every guest receives this payload unchanged;
  unique material is delivered per-VM at provision time.
- Functions follow the workstation style: `argparse` + `__<name>_help`,
  gruvbox colors via the `gruvbox_*` palette variables set in `config.fish`,
  per-item and summary output, explicit confirmation for destructive actions
  (`killport`), and Linux tools only (`ss`/`journalctl`/GNU, no `lsof`).
- Payload files are part of the repo and version-controlled. Changes are
  reviewed like code; existing guests are never silently changed when the
  payload advances.

## Packages every guest gets (Ubuntu LTS baseline)

git, vim, jq, coreutils, curl, ca-certificates, tmux, htop, fzf, eza, zoxide,
starship, fish (default shell for `artoo`), ripgrep, fd-find (`/usr/bin/fdfind`
→ symlinked as `~artoo/.local/bin/fd`, matching `fish_add_path
$HOME/.local/bin`), unzip (for `extract`), qemu-guest-agent, and tailscale
(official repository, pinned key; installed, never enrolled). The list
lives in `src/guest/vendor.zig`. Updates applied at creation (Proxmox's
`ciupgrade`); ongoing update/reboot policy defined separately.

## Account model (settled 2026-10-09)

- Default user `artoo` with sudo **prompts for password** (classic Ubuntu
  behavior); password is **unique per VM**, generated by artoo at provision
  time and stored in the platform keyring — never in payloads, manifests,
  logs, or CLI options.
- SSH: the operator's `id_ed25519` public key in `~<user>/.ssh/authorized_keys`;
  `PasswordAuthentication no` (SSH key-only), root SSH login disabled.
- Console access remains possible via the per-VM password (Proxmox UI).
